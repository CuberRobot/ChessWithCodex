### Windows 真机实测反馈（2026-09-24，来自另一台机器）

在 Windows 上跑了一遍，暴露了三个 mac 上测不到的问题，按优先级：

1. **插件在 Codex 里没起来**：仓库里的 `.mcp.json` 用的是 `python3`，Windows 没这个命令 → MCP 工具全部不可用。
   临时对策：跑 `install.ps1`（它会把配置改成本机路径）。**根治**：让安装脚本把 venv 建到用户数据目录，
   并让 `.mcp.json` 由安装脚本生成，仓库里那一份只作为 POSIX 默认值。
2. **插件目录只读**：从 marketplace 装下来的快照不可写，而 `games/`、`notes/`、`cache/`、`engines/`
   现在都在插件目录里 → 需要引入 `CHESSPLUGIN_HOME`（用户数据目录），把「代码」与「数据」彻底分开。
   **这是目前离"即插即用"最远的一步。**
3. **PowerShell 管道喂 UCI 会读错命令**（实测得到 `bestmove a2a3`）：文档里已加警告，
   工具内部走 python-chess 不受影响。

顺带确认了两件好事：原生 Stockfish 在 Windows 上（`C:\...\Downloads\stockfish\stockfish.exe`）
用 `CHESSPLUGIN_ENGINE` / `engines\stockfish.exe` 都能被找到；UCI 握手、限强选项（含 `UCI_Elo`）都正常。

## 一、交互形式与功能（按"对学棋的收益 ÷ 工作量"排序）

| # | 想法 | 解决什么 | 工作量 |
| --- | --- | --- | --- |
| 1 | **对局持久化 + 我的对局库**（PvE 存进 `games/`） | 现在刷新即重开；没有历史就做不了统计 | 1 天 |
| 2 | **错题本**：从对局里自动抽出掉分超过阈值的局面，攒成练习集，随机摆出来让你重下，对了移出队列 | 把"复盘"变成"训练"，是唯一直接提升棋力的功能 | 2 天（依赖 1） |

| 4 | **假想走法**：在自己回合随便走一步"假设着"，看引擎怎么惩罚，再一键撤销 | 有代价感知的试错，是学棋的核心循环 | 1 天 |

| 8 | **播到下一个转折点**：自动播放遇到评估跳变就停 | 陌生棋局让引擎帮你挑重点 | 半天 |
| 9 | **摆棋模式**：拖子摆一个局面 → 生成 FEN → 直接分析 | "如果我这样摆会怎样" | 1 天 |
| 10 | **候选着法（MultiPV）**：列出引擎的三个最佳走法，点哪个画哪个箭头 | 讲棋时箭头不再手写 | 半天 |

## 二、跨平台封装（做成即插即用的插件）

### 目标

在 mac / Windows / Linux 上，用户拿到这个仓库后**一条命令装好**，然后在 Codex 里就能直接用；
不需要理解 venv、不需要手动改路径、不需要自己编译引擎。

### 现在挡路的地方

| 问题 | 现状 | 处理方向 |
| --- | --- | --- |
| `.mcp.json` 写死了绝对路径 | `command: /Users/jimmy/.../.venv/bin/python` | 改成一个跨平台启动器（见下），或安装时生成 |
| venv 位置因系统而异 | `.venv/bin/python` vs `.venv\Scripts\python.exe` | 启动器自己探测；文档分两栏写 |
| 引擎路径写死 mac 的 brew 路径 | `/opt/homebrew/bin/stockfish` | 解析顺序：环境变量 → 项目内 `engines/` → PATH → 各系统常见路径 |
| 安装引擎的方式各系统不同 | mac brew / Win winget 或官网 zip / Linux apt | 安装脚本按系统分支；或提示用户装完指个路径 |
| 测试脚本假定 mac 的 Chrome 路径 | `/Applications/Google Chrome.app/...` | 按系统解析 Chrome（Win：`Program Files`；Linux：`google-chrome`/`chromium`） |
| 编译引擎需要 emscripten | 只有维护者需要 | **使用者不需要**：编好的 `stockfish-single.js` 放 `engines/`（不入库；wasm 与平台无关，一份文件全平台通用），或从 Release 下载 |

### 建议的形态

1. **零依赖启动器** `mcp/launch.py`（用系统 Python 找到 venv 或直接用它的解释器）→ `.mcp.json` 只指向它。
2. **一条安装命令**：
   - 【mac/Linux】`./install.sh`；【Win】`powershell -File install.ps1`
   - 它做四件事：建 venv + 装 `requirements.txt`；探测或下载引擎；写 `.mcp.json`（本机路径）；登记 marketplace。
3. **发布形态二选一**（**这是个要决定的事**）：
   - **随仓库带引擎**：装起来最省事，但 Stockfish 是 **GPLv3**，等于整个分发包按 GPL 走；
   - **安装时下载引擎**：仓库更干净、许可上更干净，代价是安装那一步要联网。
4. 配套：`LICENSE`（已定 MIT，见仓库根目录）、`CHANGELOG`、`docs/install-{mac,win,linux}.md`，有条件再加 CI 跑 `dev/tests/smoke.py`。

### 验收标准

- 全新机器（或全新用户目录）执行一条安装命令后，在 Codex 里说"帮我复盘一盘棋"能直接跑通；
- `dev/tests/smoke.py` 在三个平台上都能通过（浏览器检查按平台自动找 Chrome，找不到就跳过并提示）；
- 卸载 = 删掉 venv 与 marketplace 里那一条，无残留。

## 三、交互中的"会话连续性"（这个要先把可能性说清楚）

### 想要的

互动时（比如下棋），对话"不结束"——不是每一步都发一次消息、开一个新回合，
而是像会话一直开着，Codex 在旁边看着，需要时随时插话。

### 现在实际是什么样

- 棋盘是**独立运行**的：对手是内嵌 wasm 引擎，整局棋不消耗任何模型调用；
- 只有"让 Codex 点评"才把棋谱发回来，**那一瞬间开一个新回合**；
- 所以"每步都要 call 你"这件事，目前已经不存在了。真正缺的是**连续性**：
  回合结束后，界面状态与对话之间没有自动的桥。

### 哪些做不到（先说清楚，免得白期待）

- **让模型挂起一个回合、一直等用户操作**：应用没有这种"长驻回合"；
  我这边的回合在我回复完就结束了。
- **双向实时通道**（模型 → 界面、界面 → 模型都在同一回合里流动）：现有宿主接口是单向的
  （界面只能发起"新消息"），没有给我用的实时事件通道。
- 沙箱里**不能写 localStorage**（不可信来源），所以界面自己也存不下局 —— 状态必须经过我落盘。

### 可行的三种近似（建议 A + B 一起做）

**A. 事件驱动回报（推荐）**：界面在**关键事件**时自动把消息发回来——评估跳变超过阈值、每 N 手、
超时、将杀。用户什么都不用做，体验上就像"它在旁边看着"；代价是每次回报消耗一次模型调用，
但**只在关键点**，可控。

**B. 状态快照与续下（推荐）**：每局随时可以"存档"（PGN + FEN + 棋钟剩余 + 难度）发回来，
我落进 `games/` 或 `sessions/`；下次会话里读出来**接着下**。这条同时也是第一节里
"对局持久化"的正解。

**C. 真·同回合挂起**：只有应用层面提供"可暂停的会话 / 长任务"才可能；现在不做，
但值得留意（一旦有了，A 就可以升级成真正的实时陪练）。

### 验收标准

- A：一局里我至少收到 1 次自动回报（比如出现一次评估跳变），且没有打断用户的正常操作；
- B：关掉界面、隔天新开一个会话，能说"接着上次那盘下"，棋盘恢复出正确局面与棋钟。
